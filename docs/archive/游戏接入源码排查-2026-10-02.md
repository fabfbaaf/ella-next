# 游戏接入源码排查 · 2026-10-02

> 历史记录：保留当时的开发状态与验证结果。当前使用说明见 [文档目录](../README.md)。

本轮按用户要求优先检查源码，不重新制作桌面安装包。真实游戏目录只做检测和接口元数据读取，没有部署到游戏目录、打开游戏或修改存档。

## 已修复

- 桌面开发模式原先优先运行现成的打包后端，即使源码已修改仍可能启动旧服务。现在 debug 优先使用项目 `.venv` 和 `run_runtime.py`，缺少环境给出明确错误；发布模式仍只使用打包后端。
- 游戏资源查找会核对清单是否存在；源码开发可回退到 `artifacts/game-setup`，冻结运行时不回退到附近的源码目录。缺少源码资源时提示资源准备脚本。
- Windows 手动填写游戏目录时使用统一大小写匹配；选择可以持久化，多个实例继续要求明确选择。
- 后台显示当前加载器和项目资源版本，并列出缺少或哈希不同的接入文件。BLSE 将被替换时明确显示当前版本、资源版本及备份行为。
- 星露谷移动原先通过反射调用零参数的 `SetMoving*`，但游戏接口要求 `bool`。现在直接调用四个方向的 `SetMoving*(true)`，用真实游戏接口编译验证签名。
- 星露谷状态、事件和回执按提交顺序在后台发送；旧序号或过期回执返回 422/409 时不误判为端点失效。认证失败、端点不存在或网络失败只清理该请求使用的旧连接，较新的连接不会被清除。
- 骑砍普通动作自动绑定可读取的当前存档 ID，准备和最终派发前再次核对；检测到存档切换或身份丢失则不派发。动作之后或最终观察时发生存档切换，不把普通动作记为已核验。明确确认的保存、加载与新游戏操作仍允许预期的存档变化。
- GABS 进程创建失败时清除死配置、转换成可处理的桥接错误，修复下次重试一直等待无进程端口以及游戏目录接口整体失败的问题。
- 骑砍主菜单虽然可以读取接口，也不能直接启动自主游玩；后台显示等待进入存档，运行时同时检查可游玩状态。
- 本轮排查早期发现的 AppData / MSIX 文件虚拟化启动拦截已修复，保留逻辑数据路径并仅接受精确的非链接虚拟化映射；不迁移或合并用户数据。

星露谷最新 DLL 已同步到项目 `artifacts/game-plugins/Ella.StardewBridge` 和项目两份游戏接入资源，相关清单 SHA256 已更新。此前桌面安装器不包含本轮后续游戏源码修复。

## 仍需实机验收

三款游戏还需要分别在真实存档中验证动作和连续目标。GABS 未提供可验证存档 ID 时，普通动作保留现有兼容策略；高影响操作仍禁止授权。派发前检查是客户端边界检查，协议尚没有将“核对存档与执行动作”合并成游戏端原子操作。

源码开发可以运行 `pnpm --dir apps/desktop tauri dev`；修改游戏插件后需要重新编译并更新项目接入资源。模型服务还需填写实际服务地址、模型 ID 和凭据，游玩任务使用操作模型，未单独配置时按现有路由回退到聊天模型。
