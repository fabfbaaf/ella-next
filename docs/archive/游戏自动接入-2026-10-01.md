# 游戏安装与自动接入（2026-10-01）

> 历史记录：保留当时的开发状态与验证结果。当前使用说明见 [文档目录](../README.md)。

新版 Windows x64 安装包已包含游戏侧模组与加载器。安装艾拉并打开后，后台自动检测本机游戏，确认版本、进程和文件校验后部署。每 60 秒重试，退出游戏后无需重新安装艾拉。后台“游戏伙伴”可以查看原因、重新检测和选择目录。

支持范围是此安装包资源清单的边界；更早或更晚游戏版本不会自动套用这套插件。骑砍资源按 [官方 GABS 安装说明](https://github.com/BUTR/Bannerlord.GABS/blob/master/docs/setup-guide.md) 的 1.3.15 模组及 [BLSE 官方兼容发布](https://github.com/BUTR/Bannerlord.BLSE/releases/tag/v1.5.12) 准备。Minecraft 官方启动器流程依据 [Fabric 文档](https://docs.fabricmc.net/players/installing-fabric/)；第三方启动器及整合包的自动发现暂未支持。

## 首次使用

1. 关闭游戏，安装并打开艾拉，在管理后台“游戏伙伴”查看检测进度。
2. 如果检测到多个目录或 Minecraft 配置，明确选择要接入的那个；非标准安装目录也可在这里输入。选择会保存在这台电脑的艾拉数据目录中。
3. “插件已部署”仅代表接入文件完整。点击“启动并一起玩”，进入实际存档后，后台才会显示实时连接并开始目标循环。Minecraft 启动器需选“艾拉 · Fabric 26.2”或已选的兼容 Fabric 配置。
4. 对话、语音和自主游戏决策仍需要在后台配置对应模型服务；安装包不包含账户密钥或游戏本体。

## 部署与恢复

- 安装只使用资源清单指定的模组/加载器文件，复制前后校验 SHA256。实际游戏版本无法确认、游戏/启动器正在运行、重复 Minecraft 模组、目录权限不足或资源损坏都会阻止就绪状态。
- 覆盖前备份原文件并保存回执；失败会尝试回退。备份在 `%LOCALAPPDATA%/EllaNext/game-setup/backups`（使用自定义 `ELLA_DATA_DIR` 时在该数据目录中）。若其它程序同时修改了文件或游戏已经启动，保留备份并报告不能完整回退。
- 保留现有存档、其它模组、Steam 全局启动参数和 Minecraft 默认配置。新 Fabric 配置是独立项，不改启动器的 selectedProfile。遇到另一份 Fabric API 或艾拉模组，先手动移走重复文件再重新检测。
- 骑砍自动 GABS 配置位于艾拉数据目录 `gabs/auto-config`，生成本机密钥并绑定所选游戏；外部 `ELLA_GABS_CONFIG_DIR` 配置优先且不修改。
- `ELLA_GAME_SETUP_AUTO=0` 可关闭启动和周期自动部署，用于隔离验证。管理后台手动“重新检测与接入”仍是部署操作。

## 构建与验证

资源预备脚本：`scripts/prepare-game-setup.py`，从官方固定版本下载并校验，产出 `artifacts/game-setup/bundle.json`。已缓存资源可用 `--offline --tauri-resources` 重建。`scripts/package-desktop.ps1` 强制收集 `game-setup/**/*`；许可证和 SMAPI 对应源码同时保留。

- 278 项运行时测试通过（含 35 项新增自动接入测试）：首次安装、完整官方资源在临时目录部署、已有加载器保留、备份/回退、幂等、错误版本、运行中等待、重复模组、Minecraft 配置隔离、后台启动与 API。
- Ruff 与 TypeScript/Vite 构建通过；后台选择实例、部署等待和只读轮询使用隔离数据验证。
- 打包运行时在独立数据目录启动、认证、语音配置、浏览器依赖、WebSocket 拒绝未配置 ASR、优雅关闭均通过；自动游戏部署已关闭，未修改真实游戏目录。
- NSIS 资源脚本与已暂存资源逐个核对，包含星露谷 48 个文件、Minecraft 2 个模组和 8 个启动配置/库文件、骑砍 259 个文件；不包含本机 GABS 配置或密钥。

本轮未启动真实游戏、未修改存档；真实存档连接、游戏内动作与连续自主游玩仍需实机验收。安装部署就绪不等于已完成三款游戏“正常游玩”验收。
