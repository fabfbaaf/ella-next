# 开发与构建 · 1.0

当前桌面和打包目标是 Windows x64。首次安装依赖见 [快速开始](快速开始.md)。所有未注明工作目录的命令均在项目根目录执行。

## 项目结构

| 目录 | 内容 |
| --- | --- |
| `apps/desktop` | React / TypeScript 界面、桌宠与后台 |
| `apps/desktop/src-tauri` | Rust / Tauri 桌面窗口、快捷键、本地服务托管与打包 |
| `services/runtime/src/ella_runtime` | FastAPI、模型、聊天、记忆、语音、任务、应用与游戏模块 |
| `services/runtime/tests` | 隔离数据与模拟服务为主的运行时测试 |
| `packages/contracts` | 跨进程契约 |
| `game-plugins` | Minecraft、星露谷桥接源码及传输验证程序 |
| `scripts` | 打包、可选资源准备与前端状态验证 |
| `docs` | 当前使用文档、协议与历史开发记录 |

桌面与运行时版本为 1.0.0；游戏桥接插件有独立版本，目前为 0.1.0。默认数据在 `%LOCALAPPDATA%\EllaNext`，普通文件输出区在其 `workspace` 子目录。源码模式的编程工作区默认指向当前项目，可用 `ELLA_CODE_WORKSPACE` 指定其他目录。

## 开发运行

完整桌面：

```powershell
pnpm tauri:dev
```

仅启动 Python 服务：

```powershell
.\.venv\Scripts\python.exe -B run_runtime.py
```

仅预览前端：

```powershell
pnpm dev:desktop
```

前端浏览器预览不具备 Tauri 提供的会话凭据，不能代替完整产品运行。桌面自动托管服务时不用再手动启动第二个 Python 进程。不同运行时不能同时使用同一数据目录；测试和手动调试使用独立 `ELLA_DATA_DIR`。

## 常规检查

安装开发与功能依赖后，在隔离数据目录运行：

```powershell
$env:ELLA_DATA_DIR = Join-Path $env:TEMP ("ella-next-tests-" + [guid]::NewGuid().ToString("N"))
$env:ELLA_GAME_SETUP_AUTO = "0"
.\.venv\Scripts\python.exe -m pytest services/runtime/tests -q
.\.venv\Scripts\python.exe -m ruff check services/runtime/src services/runtime/tests
pnpm build:desktop
cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml
```

每次全量测试使用新的临时数据目录，避免恢复上次模拟游戏和任务状态。普通测试使用模拟接口和临时 fixture，不要求游戏安装或 `artifacts/game-setup`；默认跳过可选的真实资源集成验证。没有配置模型服务也能运行这些测试。

前端异步状态与通知队列检查：

```powershell
node scripts/test-model-form-state.mjs
node scripts/test-voice-notification-lease.mjs
node scripts/test-notification-speech.mjs
```

这些检查验证代码行为；实际音频、Office、浏览器和游戏存档仍需实机验收。不要将单元测试通过写成完整游戏游玩通过。

## Windows 桌面安装包

源码发布不附带以前的本机安装器。需要生成安装包时，先安装打包依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -e "services/runtime[packaging,browser,office,office-live,screen]"
.\scripts\package-desktop.ps1 -WithoutGameResources
```

此模式打包桌面和独立 Python 服务，不要求游戏资源。安装后运行不需要项目 `.venv`。输出目录为 `apps/desktop/src-tauri/target/release/bundle/nsis`，安装器名对应桌面版本，例如 `艾拉 Next_1.0.0_x64-setup.exe`。

`-RuntimeOnly` 只生成独立服务，可与 `-WithoutGameResources` 一起使用。直接运行 `pnpm tauri:build` 不会准备独立 Python 服务，不应作为完整安装包流程。

如要制作包含三款游戏加载器/模组资源的安装包，先按下一节准备，再运行：

```powershell
.\scripts\package-desktop.ps1
```

默认打包模式要求已缓存并校验的游戏资源；新下载的源码不能直接跳过准备步骤。第三方许可、通知与对应源码随资源清单保留，见 [第三方组件与素材](../THIRD_PARTY_NOTICES.md)。

## 可选游戏资源

游戏接入资源独立于桌面开发，不进入公开源码仓库。游戏本体、存档、账号、启动器身份信息和机器配置由使用者自行提供。

### 1. 编译 Minecraft 桥接

本次本机编译基线为 Java 25 和 Gradle 9.6.0。工程尚未提供 Gradle wrapper，需先从官方来源安装工具。项目依赖版本以 `game-plugins/minecraft/gradle.properties` 为准。

```powershell
gradle -p game-plugins/minecraft build
```

产物为 `game-plugins/minecraft/build/libs/ella-minecraft-bridge-0.1.0.jar`。支持版本固定为 Minecraft 26.2、Fabric Loader 0.19.5 与对应 Fabric API；不要混用其他游戏版本的构建产物。

### 2. 编译星露谷桥接

需要 .NET SDK、.NET 6 目标框架，以及本机星露谷与兼容 SMAPI 的程序集引用。项目使用 `Pathoschild.Stardew.ModBuildConfig`，默认查找游戏路径；非标准安装位置显式指定 `GamePath`：

```powershell
dotnet build game-plugins/stardew/Ella.StardewBridge.csproj -c Release "-p:GamePath=C:\Games\Stardew Valley"
```

将示例目录替换为实际游戏目录。产物为 `game-plugins/stardew/bin/Release/net6.0/Ella.StardewBridge.dll`；构建时关闭自动部署，不直接写入游戏目录。

传输队列验证使用独立 .NET 8 工程：

```powershell
dotnet run --project game-plugins/stardew-transport-tests/OrderedPostQueue.Validation.csproj
```

### 3. 整理桥接与官方资源

先复制自有插件产物，再从固定官方来源准备加载器/第三方模组：

```powershell
.\scripts\package-game-plugins.ps1
.\.venv\Scripts\python.exe -B scripts/prepare-game-setup.py --tauri-resources
```

准备脚本下载并校验固定资源，生成 `artifacts/game-setup/bundle.json`，并暂存到 Tauri 资源目录。骑砍归档提取要求 PATH 中可用的 `tar` 支持 7z；首次运行需要网络。完整且已验证的缓存可使用 `--offline --tauri-resources`，缺资源时会失败。该脚本重建生成目录，不能把自定义文件保存在生成的 game-setup 目录中。

骑砍游戏内模组与 GABS 服务端是两个组件。服务端需按 [第三方组件说明](../THIRD_PARTY_NOTICES.md) 单独准备；可以通过 `ELLA_GABS_EXE` 指定本机程序，或用 `ELLA_GABS_HTTP` 连接已有本机服务。不要将个人 GABS 配置与密钥纳入源码或安装包。

实际部署需关闭游戏，选择明确的实例，并核对后台的版本与资源状态。使用自定义 `ELLA_DATA_DIR` 时，让游戏继承同一个目录，保证插件能读到本机连接令牌。三款游戏的兼容范围和实机限制见 [功能状态](功能状态.md)，通信契约见 [游戏桥接协议](游戏桥接协议.md)。

### 4. 可选资源集成验证

完成资源准备后显式启用：

```powershell
$env:ELLA_DATA_DIR = Join-Path $env:TEMP ("ella-next-resource-tests-" + [guid]::NewGuid().ToString("N"))
$env:ELLA_GAME_SETUP_AUTO = "0"
$env:ELLA_RESOURCE_INTEGRATION = "1"
.\.venv\Scripts\python.exe -m pytest services/runtime/tests/test_game_setup.py -q
```

测试把准备好的 payload 部署到临时模拟游戏目录，不是进入真实游戏存档。普通测试无需设置此开关。

## 可选 Live2D

默认 SVG 可直接使用。项目保留 Live2D 接入代码，但公开源码不分发 Hiyori 原始模型、纹理、动作或 Cubism Core。自行从官方来源获取并满足各自条款后，可用导入脚本：

```powershell
.\.venv\Scripts\python.exe scripts/import-live2d-assets.py --core "C:\SDK\CubismWeb\Core\live2dcubismcore.min.js" --model "C:\Assets\Hiyori"
```

将示例路径替换为实际 SDK Core 文件和模型目录。来源、目标目录和使用条件见 [第三方组件与素材](../THIRD_PARTY_NOTICES.md)。素材授权不由项目 MIT 许可证替代。

## 公开源码快照

发布整理后的源码使用导出脚本，以排除本机数据、缓存、构建结果、未纳入发布的素材和旧 Git 历史：

```powershell
.\.venv\Scripts\python.exe scripts/export-public-source.py --output artifacts/public-release/ella-next-1.0.0
```

输出目录必须是新的目录。快照包含源码与当前文档，桌宠和应用图标使用原创资源；默认桌面开发及普通测试不依赖原工程的本地素材或游戏缓存。上传前检查这份快照的文件清单和验证结果。
