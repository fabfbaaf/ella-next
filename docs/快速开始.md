# 快速开始 · 1.0

当前发布目标是 Windows x64 源码开发环境。以下命令在项目根目录的 PowerShell 中运行。

## 1. 准备开发环境

| 依赖 | 用途 |
| --- | --- |
| Python 3.12 | 本地 FastAPI 运行时；需要创建项目根目录的 `.venv` |
| Node.js 24 | React / TypeScript / Vite 前端工具链 |
| pnpm 12.5.1 | 版本以根目录 `package.json` 的 `packageManager` 为准 |
| Rust stable MSVC 工具链 | Tauri 桌面程序 |
| Visual Studio C++ Build Tools 与 Windows SDK | Windows 原生编译；选择“使用 C++ 的桌面开发” |
| Microsoft Edge WebView2 Runtime | Tauri 界面运行环境 |

先确认 `py -3.12 --version`、`node --version`、`pnpm --version` 和 `cargo --version` 可用。若已有其他 pnpm 版本，切换到 `package.json` 指定版本后再安装依赖。

## 2. 安装依赖并启动

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e "services/runtime[dev,browser,office,office-live,screen]"
pnpm install --frozen-lockfile
pnpm tauri:dev
```

无需激活虚拟环境。桌面开发模式固定读取项目根目录 `.venv\Scripts\python.exe`，仅在全局 Python 安装依赖不能代替这一步。

首次编译会下载 Rust 与前端依赖。桌面启动后会自动托管本地服务，默认地址为 `http://127.0.0.1:8766`。公开源码的 SVG 桌宠可直接显示；Live2D、模型权重和游戏资源都是可选项。

右键桌宠打开菜单，选择管理后台；`Ctrl+Alt+E` 也可打开后台。关闭后台会隐藏窗口，可再次打开。桌宠退出时会关闭自己启动的服务和受控浏览器。

## 3. 配置模型并试聊

1. 在后台“模型路由”选择提供方，填写服务地址、实际模型 ID 与所需凭据，保存。
2. “检查已保存连接”读取模型列表；可从返回结果选择模型后再次保存。
3. “试一句”和“检查流式回复”会实际发出生成请求。字段齐全或读取列表成功，都不能代替生成检查。
4. 打开“聊天测试”创建会话并发送消息；Enter 发送，Shift+Enter 换行。

可用本机 Ollama 或支持 Chat Completions 的兼容服务。Ollama 示例地址为 `http://127.0.0.1:11434/v1`，模型 ID 使用你已安装的模型。远程地址须使用 HTTPS。操作与视觉路由未独立配置时沿用主聊天；主聊天模型是否支持图片，仍需在截图功能中验证。

密钥在 Windows 凭据库保存，后台只显示是否已配置。更换服务地址后要为新服务配置凭据；不会自动转移原服务密钥。同服务更换模型可以保留凭据。生成与语音服务可能按提供方规则计费，实际调用记入本地用量记录。

也可设置环境变量。示例见根目录 `.env.example`；**当前运行时不会自动加载 `.env` 文件**。PowerShell 示例：

```powershell
$env:ELLA_CHAT_PROVIDER = "ollama"
$env:ELLA_CHAT_BASE_URL = "http://127.0.0.1:11434/v1"
$env:ELLA_CHAT_MODEL = "你的已安装模型ID"
pnpm tauri:dev
```

后台保存的路由设置优先于环境配置；需要回到环境变量时使用对应页面的恢复环境配置操作。

## 4. 可选语音与应用

后台“语音互动”分别配置 ASR 与 TTS。ASR 使用兼容转写接口；TTS 可用兼容语音接口或 Fish Audio。首次使用允许麦克风权限，暂停监听后可试听已保存音色。点击桌宠或按 `Ctrl+Alt+V` 手动控制语音。

当前识别在说话结束后发送整句音频；回复采用流式文本与分句合成。原生增量 ASR 尚未完成。语音任务需完整交付具体计划后才能确认；没有成功播放的内容不能视为用户已听到。

“应用接入”可选择本机 Edge 或 Chrome。浏览器使用艾拉自己的资料目录，登录网站需要在该浏览器中登录。Office 文件生成不要求安装 Microsoft Office；编辑已打开的 Word / Excel 则需要 Windows、已安装的 Office 和 `office-live` 依赖。

游戏接入需要额外编译桥接插件与准备资源，见 [开发与构建](开发与构建.md)。缺少游戏资源不会影响聊天与后台启动。

## 数据、备份与故障定位

默认数据目录为 `%LOCALAPPDATA%\EllaNext`。可通过 `ELLA_DATA_DIR` 指定独立目录，通过 `ELLA_RUNTIME_PORT` 调整端口；自定义目录的游戏进程需继承同一个 `ELLA_DATA_DIR`。

后台“数据备份”可导出对话、记忆、任务、提醒、用量及模型/语音设置，先预览再确认恢复。备份不包括密钥、浏览器登录、项目工作区、生成文件、游戏与存档；恢复后需重新配置保存的服务密钥并核对未完成任务。

| 现象 | 检查方法 |
| --- | --- |
| 提示缺少 `.venv` | 在项目根目录创建虚拟环境并使用其中的 Python 安装运行时 |
| 后台未连接服务 | 查看总览的服务原因与日志路径；默认日志为数据目录中的 `runtime.log` |
| 8766 端口被占用 | 关闭冲突的服务，或在启动前设置 `ELLA_RUNTIME_PORT`；桌面只复用身份和数据目录匹配的服务 |
| 网页预览不能调用接口 | `pnpm dev:desktop` 仅提供 Vite 界面预览；完整使用需 `pnpm tauri:dev` |
| 模型配置完整但无回复 | 使用普通与流式生成检查，核对模型 ID、地址和脱敏错误信息 |
| 游戏显示资源未准备 | 公开源码不包含游戏 bundle；按可选资源构建步骤准备 |
| 语音无法确认任务 | 先检查 TTS、重新完整听取具体计划，或在后台查看后确认 |

详细能力和仍待实测的项目见 [功能状态](功能状态.md)。
