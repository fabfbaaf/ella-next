# 游戏桥接协议

艾拉运行时只连接本机游戏桥接。Minecraft Fabric 和星露谷 SMAPI 插件采用游戏主动推送状态、轮询动作与回传结果的接口；骑砍通过 GABS 工具接入。下述 `GET /snapshot`、`POST /actions` 是通用拉取型适配器契约，不是 Fabric/SMAPI 插件当前使用的端点。实际插件端点见运行时 `api.py` 的 `/api/game-plugins/{game_id}` 路由。三款游戏都尚未通过真实存档的连续游玩验收。

## 当前插件试用

按 [开发与构建](../开发与构建.md) 准备可选资源后，启动源码运行时或桌面开发模式，在后台“游戏与艾拉”查看检测与接入。兼容的唯一目录会自动准备；发现多个目录时先选择实例。接入资源来自 `artifacts/game-setup/bundle.json`，部署只修改列入清单的插件/加载器文件，并先保存被替换文件的备份。游戏运行时不会部署。

Minecraft / 星露谷插件读取艾拉数据目录 `game-bridge` 中对应的本机连接文件。骑砍使用项目中的官方 GABS 模组与依赖，以及 `artifacts/game-plugins/gabs/gabs.exe`；自动配置在艾拉数据目录生成，不从项目导入旧机器配置或凭据。也可显式配置外部 `ELLA_GABS_HTTP` / `ELLA_GABS_EXE` / `ELLA_GABS_CONFIG_DIR`。源码排查与本机状态见 [2026-10-02 历史记录](../archive/游戏接入源码排查-2026-10-02.md)。

进入真实存档后先在后台确认桥接状态持续更新，再给连续游玩目标。Minecraft 可先验收“前进、转向、破坏当前瞄准的方块并核对状态”；星露谷可验收“移动、使用当前工具、交互并核对背包或菜单变化”；骑砍需按 GABS 实际暴露的工具和当前战役状态选目标。保存游戏版本、目标、动作日志与失败时的实时状态；动作未核验时应停机，不要直接重试相同动作。

## Fabric / SMAPI 主动推送协议

- 插件向 `POST /api/game-plugins/{game_id}/state` 发送 `{"state": {...}}`，包含角色、位置、背包和附近环境。运行时收到后记录带时区的采集时间；超过 5 秒不再视为在线。
- 插件向 `GET /api/game-plugins/{game_id}/commands/next` 领取单个动作。返回 `{"action": null}` 表示没有任务；动作只派发一次。
- 游戏主线程执行动作并读取真实变化，向 `POST /api/game-plugins/{game_id}/commands/receipt` 发送 `{"action_id":"...","verified":true,"state":{...}}`。未能证实变化时传 `verified:false`，连续游玩即停止。
- 插件向 `POST /api/game-plugins/{game_id}/events` 发送游戏事件；艾拉按提醒间隔、安静时间与去重规则处理即时吐槽。
- 每个请求都要携带令牌文件中的 `Authorization: Bearer <token>`。令牌只存本机数据目录，不进入 Git。

当前 Minecraft 动作：`move`、`turn`、`look`、`jump`、`select_hotbar`、`break_block`、`use_item`、`attack_entity`、`wait`；状态包含视角、背包、当前瞄准方块、瞄准实体与附近非空气方块。当前星露谷动作：`move`、`face`、`use_tool`、`interact`、`select_slot`、`dialogue_continue`、`dialogue_choose`、`close_menu`、`chest_take`、`chest_store`、`shop_buy`、`wait`；状态包含背包、当前槽位、附近物品和地形、普通对话文本及菜单可操作性。动作限短时执行，未核验时不自动重试。实际是否能完成采集、耕作和战斗仍需要真实存档验收。

## 连接

- Fabric / SMAPI 使用游戏主动推送协议，无需配置 `ELLA_GAME_<GAME_ID>_BRIDGE_URL`。插件从 `%LOCALAPPDATA%\EllaNext\game-bridge` 读取令牌，连接本机 `127.0.0.1:8766`。
- 通用拉取型适配器可单独配置 `ELLA_GAME_<GAME_ID>_BRIDGE_URL` 与对应的 `ELLA_GAME_<GAME_ID>_BRIDGE_TOKEN`；地址只接受本机 HTTP。
- 游戏 ID：`minecraft`、`stardew_valley`、`bannerlord`。

## 观察状态

`GET /snapshot` 返回 JSON：

```json
{
  "game_id": "minecraft",
  "captured_at": "2026-09-23T12:00:00+08:00",
  "state": {
    "position": {"x": 0, "y": 64, "z": 0},
    "health": 20,
    "inventory": [],
    "last_action": {"action_id": "action-uuid", "status": "verified"}
  }
}
```

`captured_at` 必须带时区，状态不能超过 5 秒。插件应从游戏当前状态读取位置、生命、背包、任务或事件等真实信息，不能使用上次请求的预测值冒充实时观察。

## 执行动作

`POST /actions` 接收 JSON：

```json
{
  "action_id": "action-uuid",
  "name": "move",
  "parameters": {"direction": "forward", "steps": 1}
}
```

插件接受后返回 `{"action_id":"action-uuid","accepted":true}`。同一动作 ID 必须幂等；重试不能重复移动、购买、使用物品或触发事件。艾拉随后重新请求 `/snapshot`，仅当 `state.last_action.action_id` 与本次动作相同且 `status` 为 `verified` 时，才记为已核验。网络错误或状态不符会记录为结果未知，恢复时先观察，不盲目重放。

## 首款接入顺序

1. Minecraft 26.2 + Fabric：当前已实现移动、视角、跳跃、快捷栏选择、所瞄准方块破坏、物品使用、单次瞄准实体攻击与背包读取；制作与更完整的战斗流程待开发。
2. 星露谷物语 + SMAPI：当前已实现移动、面向、当前工具使用、地点交互、背包槽位选择、普通对话继续与安全菜单关闭、背包读取；具体耕种流程需在真实存档验证。
3. 骑马与砍杀 II：地图移动、事件交互和战斗中的可控动作，并读取军队与战场状态。实际游戏版本须按本机安装情况固定。

三款游戏分别在真实游戏、真实存档中完成连续游玩验收。后台的“启动游戏”负责准备接入后打开游戏；“启动并一起玩”等待进入存档后开始目标。在插件安装、连接和连续任务闭环通过前，不能把它标记为“已能正常游玩”。

## 动作安全与闭环（2026-10-01）

- Minecraft 配置失效或离开世界时，立即释放插件按下的全部按键；另以单调时钟限制动作不超过 6 秒，暂停或卡顿不能延长按键保持。终止记为未核验。
- 骑砍工具明确返回失败、拒绝或错误时，状态漂移和上游声称的成功证据不能将动作提升为已核验。更精确的目标、数量和战斗后置条件仍需逐项接入。
- 大动作目录的名称选择阶段同样接收当前状态和上一动作结果。任务完成仍由决策模型根据状态判定，尚未提供每种目标的独立确定性验收器。
- 星露谷普通对话可用 `dialogue_continue` 继续；只在文本、逐字显示进度或菜单确实变化时核验。问答选择只在选项索引和当前菜单可核验时执行，剧情过场不自动点击。`close_menu` 只关闭允许退出的普通对话、背包、箱子和商店；不强退存档、节日或未知模组菜单。
- `select_slot` 接收实际背包槽位 `slot`，协议上限为 35，插件再检查当前背包容量。对话和菜单期间停止移动与工具动作，继续/关闭/等待按当前状态提供。
- 可先用真实存档验收“与 NPC 交谈→继续普通对话→关闭→选择工具槽位→使用工具”。此链路已实现且需实机验收；购买、箱子物品交换和问答选择已有动作协议及插件实现，均需实机验收。
