# 稳定性与日常体验改进 · 2026-10-02

本轮完善桌面后台、日常语音、任务恢复、网页观察、记忆与数据备份。人物性格继续使用已选定的“外冷内热、带一点傲娇”；桌宠保持透明、无边框、可拖动、无文字对话框和提醒字幕。

## 可以直接试的变化

- 后台关闭后隐藏窗口，可以从人物菜单或快捷键重新打开。快捷键被其他程序占用时仍可启动，并在总览显示原因。Windows 重复打开会唤起现有窗口。
- 模型路由保留各自未保存的草稿；保存时禁止切换和重复提交，迟到的请求不会覆盖配置或留下过时错误。可以重新读取配置，再检查已保存服务的模型列表；连接检查不生成回答，模型实际效果仍在聊天页验证。
- 语音可直接说“暂停监听”“先别聊了”等明确指令。人物停止采集，播放确认后保持暂停；通过点击人物或后台按钮恢复。引用别人的话、提问是否能暂停不会被当成暂停指令。后台增加麦克风权限检查和已保存音色试听，远程 TTS 试听可能计费。
- 后台聊天页可选择“让语音接着这段聊”。后续语音参考最近十条文字消息；删除或归档源聊天后解除引用。已绑定的实际工作任务可以接续，但语音仍须完整交付具体计划，再确认执行，不继承文字入口的交付记录。语音自己的历史继续单独保存，并非合并成一个会话。
- 人物根据聆听、思考和实际播放音频呈现轻微姿态及嘴型；仍使用现有 Hiyori 占位资源，没有制作新的专属角色模型。
- 任务后台可修订尚未执行的步骤，保留已经完成的步骤与证据；旧批准自动失效。参数校验等明确未执行的失败与执行结果未知分开显示。源码替换保存操作收据、完整文件哈希与动作编号，删除文本也能核验，现场出现其他修改时不会误认完成或重放。
- 网页读写与后台控制共用操作锁；新增真实可见网页控件的结构化观察工具，便于下一步选择。它不会自行点击或提交，也没有实现任意网站的动态重规划。
- 记忆向量查询等待缩短，失败时回到本地文字检索，缺少的向量在后台补齐。明确修改昵称、否定某个旧偏好等会保留旧来源并标记替代关系；不同喜好可以并存。失效记忆不再进入召回。
- 游戏自主循环记录实际模型决策次数并限制总量；重复动作且观察没有实质进展时暂停。恢复旧目标保留消耗记录，避免重启后无限重复调用。等待、观察和视角动作不计为卡住。
- 总览增加首次使用清单；后台增加“数据备份”，先预览再确认恢复。

## 数据备份与恢复

ZIP 包含九个 SQLite 数据库：对话、记忆、任务、提醒和陪伴记录、用量、模型与语音服务配置、任务会话绑定，以及文字聊天参考来源。备份通过 SQLite 逐库快照读取已提交内容，包括 WAL；这些快照不是九个数据库的一次整体事务。

备份不包含 API 密钥、Windows 凭据、环境变量、浏览器登录、录音、游戏本体或存档、项目工作区与生成文件、游戏动作日志、代码修改收据，以及保存在 JSON/localStorage 的设置。它是日常数据备份，不是整机迁移。

导入前校验 ZIP 文件名白名单、哈希、数据库结构和完整性。ZIP 最大 8 MiB，单库最大 32 MiB，展开合计最大 128 MiB；预览会列出空库及覆盖影响。确认只登记待恢复状态，数据库只在下一次运行时启动、打开存储和发布令牌前替换。恢复前自动保留当前数据备份，失败或进程中断后回退。数据目录有全生命周期独占锁，第二个运行时无法恢复正在使用的数据或覆盖现有令牌。

恢复会清除任务批准、对话任务授权及交付记录，未完成任务需要重新核对；保存的服务密钥绑定断开，需要重新填写。环境变量不随包迁移，目标机器自己的环境配置仍可能生效。后台只自动重启桌面端自己托管的服务；外部运行时需手动退出并重启。导出、预览与确认时需先暂停监听及游戏操作，等待任务结束。

## 建议的试用顺序

1. 安装后打开后台，关闭后台再从人物菜单打开；确认总览连接和快捷键状态。
2. 在模型与语音页面配置实际服务，检查模型列表，在聊天页试聊；暂停监听后试听保存的音色，再恢复监听。
3. 语音中说“暂停监听”，确认之后保持安静；点击人物恢复。后台选择一段聊天接续，测试指代与任务计划再次交付。
4. 在任务页修订一个未执行的计划，确认需要重新批准；对结果未知的动作先核对现场。
5. 备份时先导出 ZIP 并保存，重新选择该文件查看预览；需要恢复时核对覆盖内容，再确认重启，最后重配保存的服务密钥。
6. 游戏进入存档后连接，设置短小目标，观察决策用量和停滞暂停是否符合实际现场。

- 模型表单 8 项、语音与通知交接 15 项、通知队列 11 项模拟场景通过；前端生产构建和 Rust 离线编译、格式检查通过。
