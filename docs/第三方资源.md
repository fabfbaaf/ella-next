## Hiyori 模型

从 [Live2D 官方 Hiyori Momose 页面](https://www.live2d.com/en/learn/sample/momose-hiyori/) 获取样本资源，阅读并接受 [素材协议](https://www.live2d.com/eula/live2d-free-material-license-agreement_en.html) 和 [样本角色条款](https://www.live2d.com/eula/live2d-sample-model-terms_en.html)。本项目不代替用户接受这些条款，也不提供原始模型镜像。

把官方样本的运行时模型文件按原有相对路径放入：

```text
apps/desktop/public/models/live2d/Hiyori/
  Hiyori.model3.json
  Hiyori.moc3
  Hiyori.physics3.json
  Hiyori.pose3.json
  Hiyori.userdata3.json
  Hiyori.cdi3.json
  Hiyori.2048/
    texture_00.png
    texture_01.png
  motions/
    ...
```

以官方下载版本的 `Hiyori.model3.json` 为准，保留它引用的文件及目录名。项目当前加载入口为 `/models/live2d/Hiyori/Hiyori.model3.json`。本机导入文件不要加入公开源码提交。

Hiyori 被列为 Live2D 原创角色。角色个别条款禁止对其设计作任何修改；素材协议另行规定可用用途、作品分发、原始素材再分发和版权表示。使用角色的公开作品应添加官方指定的版权声明，具体文本见样本角色条款的 Copyright Notice；不能把角色及其素材标为自己原创或改用 MIT。仅仅免费下载并不意味着拥有无限制再分发权。

## Cubism Core

从 [Live2D 官方 Cubism SDK for Web 下载页](https://www.live2d.com/en/sdk/download/web/) 获取适配项目的 SDK，阅读并接受 [Live2D Proprietary Software License Agreement](https://www.live2d.com/eula/live2d-proprietary-software-license-agreement_en.html)。官方 SDK 包内的 `Core/live2dcubismcore.min.js` 应原样放入：

```text
apps/desktop/public/models/live2d/live2dcubismcore.min.js
```

桌宠组件从此位置按需加载 Core；未导入时自动使用项目原创 SVG，占位资源不需要 Live2D。保留原始文件头、版权和许可信息，不把该文件提交到公开快照。发布含 Core 的独立作品或安装包前，应核对协议的发布许可条件以及第 5 节的再分发要求。前端插件 `pixi-live2d-display` 的 MIT 许可不覆盖 Core。

也可在自行获取并核对上述条款后，用本机导入脚本复制官方文件：

```powershell
.\.venv\Scripts\python.exe scripts/import-live2d-assets.py --core "D:\SDK\Core\live2dcubismcore.min.js" --model "D:\Models\Hiyori"
```

脚本不下载资源、不代替用户接受协议，也不删除原文件。导入后重启桌面。

## 静态立绘与图标

原 `apps/desktop/public/isla-pet.png` 和 `apps/desktop/src-tauri/icons/` 中的图标缺少来源与公开分发授权记录，1.0 公开快照排除这些原文件；这不构成对其权属的判断。

公开版本的静态桌宠位于 `apps/desktop/public/ella-placeholder.svg`，由本项目独立绘制，适用 MIT。发布图标由 `scripts/generate-release-icons.py` 生成紫蓝色圆形 E 图案，适用 MIT。公开快照导出时会自动生成这些替代图标；无需准备第三方模型即可显示桌宠和编译前端。Tauri 图标路径以 `apps/desktop/src-tauri/tauri.conf.json` 的配置为准。

## GABS 和游戏资源

GABS 服务端从 [pardeike/GABS 官方发布页](https://github.com/pardeike/GABS/releases) 获取。它的 MIT 许可副本位于 `scripts/licenses/GABS-MIT.txt`；分发 `gabs.exe` 时须携带适用版权和完整许可证。此服务端不同于 [Bannerlord.GABS](https://github.com/BUTR/Bannerlord.GABS) 游戏模块，后者有自己的许可证。

Minecraft、星露谷与骑砍依赖由 `scripts/prepare-game-setup.py` 从固定官方版本准备。脚本已经为 SMAPI 保存 LGPL/GPL 和对应源码，为 Fabric 保存 LICENSE/NOTICE，为 Bannerlord 模块保存各自许可。生成目录 `artifacts/game-setup/` 和下载缓存属于本机或发行包准备内容，不属于公开源码快照。游戏本体、存档、机器配置与用户数据不随源码发布。

公开源码与完整安装包是两种分发形式。制作安装包时还需清点实际进入包内的 Python、前端、Rust 依赖和运行时资源，保留适用第三方通知。本说明不代表所有传递依赖的二进制再分发已经完成核验。
