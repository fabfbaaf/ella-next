# 日常使用改进 · 2026-10-01

本轮将文字聊天、语音工作请求和实际任务结果接到同一套处理流程，并补上后台语音配置及无字幕提醒。桌宠继续保持透明、无边框、可拖动的 2D 角色，不增加前端对话框。

## 现在可以怎样使用

- 在后台文字聊天或桌宠语音中提出工作请求，例如“在艾拉工作区创建一份 Word 文档，文件名是学习安排.docx，内容是周一学习英语、周二学习数学”。艾拉会选择已接入工具，给出具体计划；需要确认时可说或输入“确认执行”。
- 近期对话中的“把刚才的内容保存下来”等请求，会结合最近 10 条消息、当前绑定任务和实际工具目录进行解析。每条上下文最多 2000 字；同样的近期内容作为独立数据传到任务规划器，用来填写具体内容，不只是送到意图分类步骤。历史指令和网页引用不会变成新的操作请求；目标、文件或保存位置不明确时先澄清。
- “完成了吗”读取实际任务状态，后台聊天页的当前工作卡片也会定期刷新，提供完整计划和核验记录入口。没有绑定任务时明确说明没有可核验进度；任务失败、暂停或需要核对时不说已经完成。
- “取消任务”可以取消尚未执行的计划；执行过程中停止只表示停止继续动作，已经发出的动作需要核对，不能假定撤销。同一请求和上下文的重试复用原任务及最新状态。
- “提醒我十分钟后喝水”可设置单次提醒。开启通知语音并配置 TTS 后，到期通过声音提醒，人物旁边不显示文字字幕。

文字与语音使用相同的处理逻辑，历史记录与任务绑定仍是不同会话。跨入口指代、很久以前的内容和任意含糊请求不能保证自动解析；遇到不明确的目标应补充信息。

## 确认、实际证据与恢复

需要确认的计划展示具体工具及参数，批准绑定内容指纹。文字会话必须实际保存完整计划回复；语音必须把具体计划完整播放并确认到已听历史，才能通过“确认执行”批准。播报被打断会重新展示/播报参数；内容较长时到任务后台查看完整计划。计划变化后旧批准失效，重新确认不会直接执行旧内容。未启用 TTS 或单轮合成失败时，未播出的回复不进入已听历史，语音合成未就绪时不能通过语音批准。即使随后恢复 TTS，也必须先重新完整交付计划再确认。

已批准但还未开始的任务重启后可再次确认并恢复。已发出的动作结果不明时暂停，核对现场后才能继续，避免直接重放。分类输出无效、规划失败或工具不能核验都不会被当作完成。

生成文件可以引用此前读取/搜索步骤的实际证据：只允许补全文本内容、Word 段落、Excel 行或 PPT 页面，不能改目标文件、覆盖设置、工具或新增步骤。运行时检查引用原文，保存具体生成参数，然后要求再次确认才写入。因此“读取资料→据此生成文档”会有读取计划和具体内容两次确认。重启、网络回执丢失或核对现场时使用已保存参数，不重复生成内容。

搜索回执包含真实标题、网址和摘要；若需要正文，应安排对已知网址的读取步骤。当前机制不能自行新增未批准的浏览器操作。原文引用核验只证明引用存在，生成内容的事实和推论仍需审阅。

## 语音配置和播报

后台“语音互动”现在分别保存 ASR 和 TTS 的服务地址、实际模型 ID、音色 ID 和密钥，识别与合成可以连接不同服务。ASR 使用兼容 OpenAI 的转写接口；TTS 支持兼容 OpenAI 的语音接口和 Fish Audio。Fish 音色填写 reference_id，本地兼容服务仍可通过本机地址接入。

非敏感配置在用户数据目录的 `voice.sqlite3`，密钥在 Windows 凭据库；ASR、TTS 以及不同协议/主机/端口分别绑定，切换服务不沿用原服务密钥。可以清除保存的密钥或恢复环境变量设置。保存配置时需先关闭实时监听、等待本轮处理与播报结束；保存后下次语音请求生效。“配置已齐全”只说明配置字段及凭据完整，实际响应仍由首次使用验证。

提醒和任务结果使用已配置的 TTS，不需要新增字幕。通知等待对话空闲，取得独占许可后暂停采集、确认监听连接关闭，再合成和播放。手动录音、用户已开始说话、识别/思考/回复、安静时段或用户主动暂停时，通知不会抢占；许可释放后按此前设置恢复连续监听。只在音频完整播放后记录已播报，打断不算听完；失败保留通知和错误。后台也可以关闭通知语音。

## 简单试用步骤

1. 用最新安装包启动，打开后台总览，确认本地运行时连接。到“模型路由”配置可用聊天模型；操作模型可独立设置，未单独设置时沿用聊天模型。
2. 先在“聊天测试”输入上面的 Word 示例，核对完整工具参数后输入“确认执行”。查看当前工作卡片，再问“完成了吗”，同时检查工作区里的实际文件。
3. 在“语音互动”关闭实时监听，分别保存 ASR、TTS 和音色；不要把“配置已齐全”当成已验证服务。随后开启连续监听，点击角色或按 Ctrl+Alt+V 控制语音，试说同样的工作请求。
4. 完整听完具体计划再确认。也可在播放途中打断后确认，检查艾拉是否要求重新交付计划，而不是直接执行。
5. 开启“语音播报提醒与任务结果”，在非安静时段设置一条短时提醒。分别测试对话占用、用户主动暂停和恢复，确认通知只在允许时播放；错误到后台查看。
