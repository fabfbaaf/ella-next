# 模型接入源码改进 · 2026-10-02

本轮在 ella-next 源码项目完成模型路由、兼容请求和后台配置检查的改进。全部验证使用模拟接口及临时数据库，没有读取用户密钥、发出真实模型请求，也没有打安装包。

## 已修复的问题

| 原问题 | 现在的行为 |
| --- | --- |
| 操作提供方换成 Gemini，仍可能取 DEEPSEEK_API_KEY | 根据提供方选择对应环境密钥；非 DeepSeek 操作提供方不再默认填写 DeepSeek 模型 ID |
| 视觉模型无条件继承主聊天密钥；主聊天用代理时视觉地址可能回到官方服务 | 同提供方默认沿用实际主聊天地址；只有协议、主机、有效端口相同才继承凭据 |
| 通用厂商环境密钥可能发往自定义代理 | GEMINI_API_KEY、DEEPSEEK_API_KEY、OPENAI_API_KEY 仅用于对应官方 origin；代理须显式填写 ELLA_<路由>_API_KEY |
| 首次把同服务环境配置保存到后台，密钥留空后丢失 | 将已有同 origin 凭据保存到该路由的 Windows 凭据库；显式清除仍有效，不跨服务复制 |
| 粘贴完整聊天端点后重复追加 /chat/completions | 保存与环境配置统一规范常见完整端点；保留代理自定义基础路径 |
| Gemini 模型列表的 models/ 前缀或展示名导致错误 ID | 仅规范 Gemini 的对应 ID，保留其他服务的自定义别名 |
| 无效端口、坏 IPv6 URL 或空错误消息导致内部异常 | 配置安全拒绝无效地址；状态页和错误处理不会因此崩溃 |
| 先截断错误再隐藏密钥，可能显示密钥前缀 | 先对完整错误脱敏，再裁剪显示长度 |
| HTTP 200 的 SSE error、空流、提前 EOF 被当作成功 | 明确失败；成功流须有文本及 finish_reason 或 [DONE] 结束标记 |
| 模型长度截断、内容过滤或未支持的原生工具调用被当作完整回答 | 返回具体错误，避免把截断的操作 JSON 交给执行流程 |
| 注入了跟随重定向的 HTTP 客户端时，凭据可能随请求跳转 | 文本、视觉、流式与模型列表请求显式禁止自动重定向 |
| DeepSeek 流式缓存命中 Token 未计入 | 与普通生成统一读取缓存用量；服务未上报的数字保持未知 |

官方 OpenAI 主机的输出上限字段使用 `max_completion_tokens`，其他兼容服务保留 `max_tokens`，不靠未知模型名称猜参数。OpenAI 文档已将旧字段标为弃用，并说明其不适用于 o-series。[接口依据](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)

Gemini 的官方兼容基础地址为 `https://generativelanguage.googleapis.com/v1beta/openai`，支持通过兼容模型列表接口读取可用模型。[Google 官方说明](https://ai.google.dev/gemini-api/docs/openai)

## 后台怎么用

1. 选择配置位置与提供方预设。预设包括 Ollama、Gemini、DeepSeek、OpenAI，以及其他 Chat Completions 兼容服务。切换预设会填写对应地址，并清除旧模型和待输入密钥，避免配置错配。
2. 填写实际模型 ID 和凭据，保存。字段齐全只说明地址、模型和凭据完整。
3. 点击“检查已保存连接”，读取服务模型列表。可从返回列表选择模型后重新保存；检查本身不生成文字。
4. 点击“试一句”检查普通生成，点击“检查流式回复”检查完整 SSE 链路。两项各发送一次固定短提示，上限 128 个输出 Token，30 秒超时；显示回复预览和耗时，并记录真实上报的用量。

生成检查直接走指定模型提供方，不调用联网、记忆、任务工具或第二层人格润色。它证明该路由当前可以生成文字；不代表模型已经具备可靠工具规划或图片理解能力。视觉路由的图片能力仍需在截图功能中验证。较多内部推理的模型可能需要更大的生成上限，短检查不能替代完整业务验证。

操作、视觉路由未单独设置时，状态页与检查接口均沿用主聊天。继承路由选取列表模型时，会同步主聊天服务地址与提供方，再创建独立配置，不再将本地模型 ID 保存到云服务地址。

当前统一支持 Chat Completions 兼容协议。Gemini 原生 generateContent、OpenAI Responses、Ollama /api/chat 原生地址会得到明确提示，尚未实现独立原生协议适配。

## 验证

- 模型相关与日常接口：168 项通过，包含错误脱敏、空错误、HTTP 200 error、SSE 截断、结束标记、参数字段、缓存用量、禁止重定向、凭据 origin、模型列表、生成 API 与继承路由。
- 表单异步状态：13 个场景通过，涵盖迟到响应、草稿保存、路由切换、重复点击、卸载、预设切换与继承模型选择。
- TypeScript、前端生产构建、Ruff：通过。前端现有 Live2D 主包仍有大小提示，不影响构建。
- 最终后端全量回归：578 项通过（全新临时数据目录），仅两项已有 FastAPI / Starlette 测试客户端弃用提示。

完整回归每轮使用新临时 ELLA_DATA_DIR，并设置 ELLA_GAME_SETUP_AUTO=0。复用旧测试目录会恢复模拟游玩的 paused 状态，导致高影响游戏接口按设计返回 409；这不属于模型接入回归。

本轮没有重现用户真实 Gemini 请求，因此不能断言之前某次 HTTP 400 的唯一原因。现在后台可直接检查模型列表、普通生成和流式生成，并显示脱敏后的上游原因。

## 后续可改进的能力

- 新配置先验证凭据和列出模型的向导，减少首次手填 ID 的负担。
- 保存模型的上下文长度、输出上限和超时设置，并按模型能力管理文字、图片、流式、操作 JSON 检查结果。
- 当确有业务需要时补独立原生协议适配；当前“兼容服务”名称不代表支持所有厂商的原生 API。
- 使用真实服务验证截图、语音首句延迟与完整任务规划，特别是代理是否保留 usage 和 SSE 结束事件。
